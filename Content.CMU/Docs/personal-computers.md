# Personal computers and the ExtraNet

Working personal computers for colony, corporate and USCM maps. Each one boots an in-universe OS
with a small set of programs. The main program is a browser for the ExtraNet, a fake network of
pages written by contributors and shipped with the game.

## Goals

- Give the hundreds of mapped desktops a use: lore, colony notices, manuals, corporate memos.
- Make adding a page as easy as adding a guidebook entry: one YAML block and one markup file in a PR.
- The browser only renders our own markup. It has no HTTP, no scripts and no player uploads.

## Pieces

### OS themes (`cmuComputerOs` prototype)

One system with themed skins, picked per computer:

| Id             | Boots as                               | Used by                 | Look                          |
|----------------|----------------------------------------|-------------------------|-------------------------------|
| `CMUOsSeegson` | Seegson, then the colony network name (GARRISONLINK) | colony and civilian PCs | green phosphor on near black  |
| `CMUOsWeyland` | Weyland-Yutani corporate terminal      | corporate PCs, WY labs  | amber phosphor                |

Each theme sets the boot logos and lines, palette, accent, sounds, start button label, wallpaper,
home page, the networks the computer can reach and the documents every such computer has.

### Boot splash

The tube warms up, then each entry in `logos` builds in interlaced lines and holds; the boot log and
progress bar run under the last one. Clicking skips it. Logos live in
`Content.CMU/Resources/Textures/CMU14/PersonalComputers/Logos/`. A PNG is revealed and pulses; a `.rsi`
plays its `logoState` (default `logo`) frames. A path whose file does not exist is skipped, and with
none the OS name is animated instead, so a new logo is dropped in without code changes.
The PNGs are generated by `Content.CMU/Design/PersonalComputers/LogoPixelArt/logo_pixel_art.py`; the
Weyland-Yutani one reuses the colony ATM's boot mark from the ATM generator.

### Desktop

After the splash: wallpaper (the OS `wallpaper` texture, or a faint grid with the OS name), icons,
and a taskbar with a start menu (programs, shut down), a button per open window and the shift clock.
**Pop out**, beside the terminal window's close button, moves the whole screen into an OS window of
its own (another monitor, larger). Closing that window brings it back; walking away from the computer
closes both.

Program windows drag by the title bar, resize from the corner, minimize, close, and maximize on a
double click of the title. Program icons are 16x16 PNGs at
`Textures/CMU14/PersonalComputers/Icons/<os id>_<program>.png` (lowercase, e.g. `cmuosweyland_files.png`),
falling back to `<program>.png` and then to a drawn glyph. The desktop shows them at 2x; the start menu,
taskbar buttons and window title bars at 1x.

Programs:
- **ExtraNet**: address bar, back, forward, home and directory.
- **Files**: read only documents from the OS `documents` list plus the computer's own `documents`
  (mappers can leave notes on a PC). Same format as pages.
- **System**: OS, terminal name, networks and uptime.

### Computer (`CMUPersonalComputerComponent`)

Added to the existing `RMCPersonalDesktop` prop (443 placements over 30 CMU maps) with a small
`# CMU14` tagged edit, so every mapped desktop works without remapping. Fields: `os`, and `networks`,
`homePage` and `documents`, which override or extend the OS defaults. `CMUPersonalDesktopWeyland`
is the corporate variant for mappers.

### ExtraNet sites (`cmuNetSite` prototype)

```yaml
- type: cmuNetSite
  id: CMUNetSiteSeegsonColony
  address: colony.seegson.net     # what players type in the address bar
  title: cmu-net-site-seegson-colony
  networks:                       # which computers can reach it
  - CMUNetPublic
  root: /ServerInfo/CMU14/ExtraNet/Seegson/Colony/
  pages:                          # path -> file under root; "" is the site's index
    "": index.xml
    housing: housing.xml
    jobs/miner: jobs_miner.xml    # reached as colony.seegson.net/jobs/miner
```

Pages are guidebook-style XML documents, so authors get the existing tags: headings (`#`, `##`,
`###`), lists, `[bold]`, `[italic]`, `[color]`, `<Box>`, `<Table>`, and images with
`<CMUGuideImage Path="/Textures/....png" MaxHeight="90"/>`. ExtraNet adds:

| Tag | What it does |
|-----|--------------|
| `[netlink="Text" link="host/path"]` | Link to another page. Without `link` the text is the address. |
| `<CMUNetStyle Background="#0B1630" Text="#D8E6FF" Heading="#FFD24A" Link="#7FD3FF" Font="Display" BackgroundImage="/Textures/....png" BackgroundMode="Tile"/>` | Page look; every attribute optional. Fonts: `Sans` (default), `Display`, `Mono`, `Terminal`, `Pixel`. Modes: `Stretch`, `Tile`, `Center`. |
| `<CMUNetSprite Rsi="/Textures/....rsi" State="arcade" Scale="3" Align="Center"/>` | An RSI state, animated when it has frames. |
| `<CMUNetBlink Rate="0.5">...</CMUNetBlink>` | Children blink. |
| `<CMUNetMarquee Text="..." Speed="70" Color="#FFD24A"/>` | Scrolling ticker. |

A site's `style:` block in YAML sets the same fields for all its pages; a page's `CMUNetStyle`
overrides it. See `colony.seegson.net/radio` and `intranet.wy/memo` for examples.

Linking:

```xml
<Document>
# Seegson Colony Services
Welcome, colonist. Choose a service below.

- [netlink="Housing assignments" link="colony.seegson.net/housing"]
- [netlink="Employee handbook" link="intranet.wy/handbook"]
</Document>
```

A link to a site the computer can't reach shows the OS's "NETWORK ACCESS DENIED" page.
A missing address shows a themed 404.

### Boards (round postings)

A site with a `board:` block shows the round's postings under its index page. Only the listed `posters`
jobs (exact ids, so list every variant) see the composer and publish; anyone at a computer that reaches the
site comments; ghosts cannot. Admins publish anywhere and get a Delete button. The server names the author
and role, caps titles (80), bodies (2000) and comments (300), rate limits posting (30 s) and commenting
(5 s), keeps 40 postings and 60 comments per posting, and admin logs everything. Player text is drawn as
plain text. Postings reset every round. Defined in `boards.yml`:

| Address | Board | Posters |
|---------|-------|---------|
| `herald.colony.news` | The Colony Herald | journalist |
| `admin.colony.gov` | Colony Administration | administrator, deputy administrator |
| `command.govfor.mil` | Garrison Command | GOVFOR commanding, executive and staff officers (all force variants) |
| `embassy.upp`, `embassy.twe`, `embassy.ua`, `embassy.icsc`, `embassy.cca` | Embassies | each ambassador |

### Tabs and site art

A site's `tabs:` list (title locale id and page `path`, empty for the index) draws a tab strip above its
pages in the site's colours, the open page filled. Each board site has a masthead banner and emblem under
`Textures/CMU14/PersonalComputers/Sites/<Site>/`, generated by
`Content.CMU/Design/PersonalComputers/SiteArt/<Site>.py`, and three lore tabs.

### Colony editions (per map pages)

Each round's computers learn the round's map when they spawn. `{colony}` in any page becomes the map's
`mapName`, and a site serves `<root>/<map id>/<file>` when it exists, else the generic `<root>/<file>`.
A new map needs nothing in this system: it gets the generic pages under its own name. To give it custom
pages, add `<root>/<map id>/index.xml` (and any of `history.xml`, `classifieds.xml`, `about.xml`).
`colonies.yml` is optional and only lets several maps share one folder (all Stable Garrison maps use
`StableGarrison/`). Herald mastheads are rendered by `SiteArt/Herald.py --colony "NAME" --out
.../Sites/Herald/<folder>`.

### Platoon editions (GOVFOR pages)

A site with `platoonPages: true` also changes with the round's GOVFOR platoon. The server writes the
platoon's id (`SelectedGovforPlatoon`) into every computer's `Platoon` field when it spawns, and checks every
few seconds after that, since the platoon is often voted in or set by an admin after the map's computers
spawned. The browser then serves the first of `<root>/<platoon id>/<file>`, `<root>/<colony>/<file>` and
`<root>/<file>` that exists, so a platoon page wins over a colony page, and any page a platoon leaves out
falls back to the colony or generic one. Platoon pages do not combine with colony pages.

`command.govfor.mil` uses it: `Boards/Govfor/<platoon>/` has the platoon's own `index.xml`, `garrison.xml`,
`guidance.xml` and `zones.xml`, each with a `CMUNetStyle` line for the platoon's colours and a letterhead
built from its real patch and flag sprites. The tabs and the board under the index stay the site's own.
To add a platoon, make a folder named exactly after its `platoon` prototype id and copy the generic pages
in as a start; keep what GOVFOR does at the colony, the zones and the rules for troops, in the unit's voice.
`CMUExtraNetTest` checks the folder is a platoon id, every page parses and links resolve, and every file in
it stands in for one of the site's pages. `ComputersFollowGovforPlatoon` covers the server side.

### Networks

`CMUNetPublic`, `CMUNetSeegson`, `CMUNetWeylandYutani`, `CMUNetUSCM`, `CMUNetCMB` (the Marshals), `CMUNetSecurity`
(colony security) and `CMUNetDeep` (hacked terminals) (`cmuNetwork` prototypes).
A site lists the networks it is on. A computer lists the networks it can reach. A corporate terminal reaches Public and
Weyland-Yutani. A colony desktop reaches only Public. A dark terminal (see below) reaches none of them, only the deep
web if it is hacked.

### Retuning terminals and the colony security network

A multitool on a terminal opens a radial menu: **View logs**, **Hack terminal** and **Retune network**. Retuning
uses the access tuner's first stage only: match the three dials to the terminal's carrier and lock before the trace
runs out. It needs the same engineering skill as the hack (`CMUDeepWebHackable.skillLevel`), shares its lockout,
and its trace is `retuneTrace` (40 s) scaled by skill like the hack's. Only terminals that can be hacked can be
retuned; bridged consoles cannot.

A terminal is either on the colony network (its own or its OS's networks) or **dark**. The tuner cannot put a terminal
on the corporate or bureau networks: those run on their own keyed lines, so the only choices are on and off the
colony carrier. A dark terminal (`CMUPersonalComputer.dark`, which mappers can also set):

- reaches no colony network: colony sites show an OFFLINE page, mail and the colony boards stop answering;
- keeps its files, notes, wallpaper, saved links and its own log, which still records every page it opens;
- keeps the deep web if it is hacked (scans, ad pages, the market, hacker tools, deep boards);
- reports nothing live: no Marshal lookup alerts, nothing on the security log, nothing for the packet sniffer,
  and it cannot be traced (a trace running when it goes dark comes back lost);
- reboots onto the new carrier, closing its screen on anyone using it; its network light goes out (it shows on examine).

Going dark is the last thing it reports: security's log gets *Terminal #N went dark at <area>*, and its map keeps
the terminal at that spot, blinking red, even if it is carried off. Someone has to go and look, and an engineer
with a multitool can read what it did in its own log. Retuning it back puts it on the network and the map again.

The colony security site, `security.seegson.net` (`CMUNetSecurity`), is on the colony security desk
(`CMUPersonalDesktopSecurity`, which opens on it), on bridged colony security consoles (the `networks:` block in
`bridge.yml`: the security department console and the colony security camera monitors) and on the Marshals' OS. It
has two live panels (`CMUSecurityNetSystem`):

- **Unauthorized use**: cards refused at a reader, terminals going dark and coming back, maintenance ports opened
  for a hack, logs wiped or edited, and deep lookups from unhacked terminals (which the Marshals also get). Each line
  has the shift time, terminal number, area and, where known, the name on the card: the refused card, or the card
  in the reader at the time.
- **Terminal map**: every terminal on the grid, coloured by status: on, logged in, switched off, no power, hacked
  (when security saw the hack start, so a terminal hacked while dark never shows it) and OFFLINE at its last known
  position. Dark and hacked terminals are listed under the map to be checked on foot.

Pages ship in the client's resources, so this is in-universe flavour, not a secret. Content that
must stay hidden from players (passwords for an objective, for example) has to come from the
server in a later phase.

## Contributing pages

Pages are content, not code: a new site is an XML folder, one YAML entry and a few locale strings, sent as a
pull request like any other change. Nothing is uploaded in game.

### The easy way: a site package

A site package is one folder that is the whole site: a `site.yml`, its pages and its images. Drop it anywhere
under `Content.CMU/Resources/ServerInfo/CMU14/ExtraNet/` (new ones go in `Packages/`) and the game picks it up
at startup. Nothing else to edit: titles, tab names and board labels can be plain text, `root` can be left out
(it is the package's folder), and pages refer to their own files as `./banner.png`.

`Packages/LostAndFound/` is a complete example. The ExtraNet editor (hosted at https://extraneteditor.ignies.net,
source at https://github.com/Ignies/ExtraNet-Editor, a static web page anyone can host) builds packages from blocks
with a live in-game preview, picks real game sprites, and exports a zip to drop in and open a pull request with. Its
Library opens every site already in the game for curating, and its emulator runs the whole PC in a browser.

### By hand, with the shared files

The sites that came with the feature use shared files instead; new sites can too:

1. Make a folder for it under `Content.CMU/Resources/ServerInfo/CMU14/ExtraNet/`:
   `Public/<Site>/` for the open ExtraNet, `Deep/<Site>/` for the deep web, `Retro/<Site>/` for the 80s style
   sites, `Boards/<Site>/` for boards. Write `index.xml` and any tab pages in it.
2. Add a `cmuNetSite` to `Content.CMU/Resources/Prototypes/CMU14/PersonalComputers/` (`sites.yml` for public
   sites, `boards.yml` for boards, `deep_web.yml` for deep sites). Give it an address, a title, its networks,
   its root folder, its pages, a `style:` block and `tabs:`.
3. Add the title and tab names to `Content.CMU/Resources/Locale/en-US/CMU14/personal-computers.ftl`.
4. Art: a banner goes in `Content.CMU/Resources/Textures/CMU14/PersonalComputers/Sites/<Group>/<Site>/banner.png`
   with an `attributions.yml`, shown at the top of every page with
   `<CMUGuideImage Path="/Textures/CMU14/PersonalComputers/Sites/<Group>/<Site>/banner.png" MaxHeight="150"/>`.
   **Reuse the game's real sprites for anything that exists in game** (machines, items, xenos, people): put them
   on the page with `<CMUNetSprite>` or `<CMUNetAd>`, or composite their RSI frames into the banner. Only paint
   backgrounds, text and things with no sprite. The banner generators in
   `Content.CMU/Design/PersonalComputers/SiteArt/` show how.
5. Test: run the YAML linter and `CMUExtraNetTest`, then look at it in game (see Testing below).

Rules the test enforces: addresses are lowercase hosts without slashes and unique; every site has an index
(`""`) page; every page parses; every tag is valid (colours, fonts, sprite paths and states, ad ids); every
`netlink` points to a page that exists. In page text, avoid `<`, `>`, `&` and double quotes outside markup.
`{colony}` in any page becomes the round's colony name.

### Page tags

The guidebook basics work (`#` headings, lists, `[bold]`, `[italic]`, `[color=#hex]`, `<Box>`, `<Table>`,
`<CMUGuideImage>`), plus:

| Tag | What it does |
|-----|--------------|
| `[netlink="Text" link="host/path"]` | A link. `net://random` goes to a random listed site the reader can reach; `cam://<network>` opens a camera grid (deep web only). In a site package, links to other hosts are not checked, so a package can link anywhere. |
| `<CMUNetStyle .../>` | Page colours, font and background image (see above). |
| `<CMUNetSprite Rsi="/Textures/....rsi" State="..." Scale="2" Align="Center"/>` | A game sprite, animated if it has frames. |
| `<CMUNetBlink Rate="0.5">...</CMUNetBlink>` / `<CMUNetMarquee Text="..." Speed="60" Color="#hex"/>` | Blinking and scrolling text. |
| `<CMUNetAd Id="CMUDeepAdMre" Flip="true"/>` | A product ad drawn from an item's own sprite (`deep_ads.yml`). |
| `<CMUNetPopup Title="..." Text="..." Link="host" LinkText="..." Icon="/Textures/....png" X="0.6" Y="0.2" Delay="1.5"/>` | A pop up over the page, inside the browser window. |
| `<CMUNetWallpaper Id="CMUWallpaperSynthwave"/>` | A wallpaper players can put on their desktop (`wallpapers.yml`). |
| `<CMUNetRecipes Kind="Food" Group="Savory"/>` | The cookbook, built live from the game's microwave recipes. |
| `<CMUNetArcade/>` or `<CMUNetArcade Game="HuggerRun"/>` | The arcade: with no `Game`, a tab per cabinet (Hugger Run, Tracker Reflex); with one, just that cabinet. The games play from the keyboard: click the screen, arrows / WASD / numpad to play, Space to start, Esc to let go. |
| `<CMUNetSportsbook/>`, `<CMUNetSpaceGpt/>` | The sportsbook, with a tab per sport, each on its own schedule; SpaceGPT. |
| `<CMUNetMarket/>` | The deep contraband market. |
| `<CMUNetCmbPanel Kind="Alerts"/>` | A Marshals' panel: `Alerts`, `Map`, `Faxes` or `Records`. |
| `<CMUNetSecurityPanel Kind="Log"/>` | A colony security panel: `Log` (unauthorized use) or `Map` (terminal map). |

### Boards

Add a `board:` block to a site to give it round postings under its index page:

```yaml
  board:
    postLabel: cmu-net-board-classifieds-post   # composer button
    empty: cmu-net-board-classifieds-empty      # shown with no postings
    posters: [AU14JobCivilianJournalist]        # jobs that may post (exact ids)
    posterWhitelist: { components: [CLFMember] } # or anyone matching this
    anyonePosts: true                           # or everyone (forums, classifieds)
    showTerminals: true                         # show "Terminal #N" on postings
    bounties: true                              # cash rewards from the poster's account
    leaks: true                                 # random hacker leaks land here (deep only)
    hijackable: true                            # insurgents can seize the front page
```

### Deep web sites

Deep sites sit on the `CMUNetDeep` network and should be `unlisted: true`. Every round each one gets a new
random address (ending in `aliasSuffix`, default `.deep`, e.g. `.file` or `.cam`), so the name in its
prototype is only for links between pages. `hidden: true` keeps a site out of scans: it can only be reached
through the ad maze, whose chains are laid out fresh every round. Players find unlisted sites with The
deeps.exi's scan.

### Ads, wallpapers and art for the ad maze

- Product ads (`deep_ads.yml`, `cmuDeepAd`): an `entity` (drawn from its sprite) or a `gear` starting gear (a
  dressed person), plus brand, product, slogan, price, colours and an optional badge state.
- Wallpapers (`wallpapers.yml`, `cmuWallpaper`): a name and a 960x600 PNG, offered on a page with
  `<CMUNetWallpaper>`.
- Ad maze art: every `banner_*.png`, `icon_*.png` and RSI state in `Textures/CMU14/PersonalComputers/Sites/Ads/`
  and `.../Retro/` is picked up automatically. Slogans, headlines and pop up texts are localized datasets in
  `deep_web.yml`.

### Testing

- `CMUExtraNetTest` validates every site; the other `CMU14.PersonalComputers` tests cover boards, the deep
  web, sessions, bounties and the rest. `CMUComputerRetuneTest` covers dark terminals and the security log and map.
- `--cvar cmu.panel_preview=pc` on the client walks the desktop through every OS and site without a round.
- `Content.CMU/Design/PersonalComputers/Test/server.toml` starts Stable Garrison with no lobby, spawns players
  as the journalist next to a colony desktop, a W-Y desktop and a Marshals' console, with an access tuner,
  engineering skill and insurgent status, and leaks every minute.

## Feature switches

Every feature is a server CVar, so admins can switch any of them off mid round, e.g.
`cvar cmu.pc.deep_web false`. Clients hide what is off.

| CVar | Feature |
|------|---------|
| `cmu.pc.enabled` | Everything |
| `cmu.pc.needs_power` | Terminals need the area's equipment power |
| `cmu.pc.boards`, `cmu.pc.shortcuts`, `cmu.pc.login`, `cmu.pc.logs` | Postings, saved links, ID card logins, terminal logs |
| `cmu.pc.deep_web`, `cmu.pc.leaks`, `cmu.pc.hijack`, `cmu.pc.camera_tap` | Hacking and the deep web, leaks, Herald hijack, camera taps |
| `cmu.pc.bounties`, `cmu.pc.wire`, `cmu.pc.lore_events`, `cmu.pc.company_spin` | Bounty money, the Herald wire, forums reacting to the round, Company spin |
| `cmu.pc.trace`, `cmu.pc.log_tamper`, `cmu.pc.cmb` | Marshal traces, wiping and forging logs, the CMB network |
| `cmu.pc.retune`, `cmu.pc.security_net` | Retuning terminals dark (off: dark terminals are back on the network), the colony security network |
| `cmu.pc.mail`, `cmu.pc.notes`, `cmu.pc.wallpapers` | Mail, notes, wallpapers |
| `cmu.pc.arcade`, `cmu.pc.betting`, `cmu.pc.spacegpt` | Arcade, sportsbook, SpaceGPT |
| `cmu.pc.market`, `cmu.pc.hacker_tools` | Deep market, packet sniffer and camera loop |

Ghosts can turn off SpaceGPT questions for themselves with `cmu.pc.spacegpt_ghost_polls`.
